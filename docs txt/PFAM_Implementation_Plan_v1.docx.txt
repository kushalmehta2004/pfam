# PFAM — Cursor Rules
# Profit-First Ad Manager | Solo Build | Full SRS Implementation
## Project
Building a multi-tenant SaaS called PFAM (Profit-First Ad Manager).
D2C e-commerce brands connect Shopify + Meta Ads + Google Ads.
System calculates true net profit per campaign and automates pausing unprofitable ones.
## Stack
Frontend: Next.js 14 App Router + TypeScript + Tailwind + shadcn/ui → deployed on Vercel
Backend: Python 3.12 + FastAPI + SQLAlchemy 2.0 + Alembic → deployed on Railway
Database: Neon (serverless PostgreSQL 15)
Auth: Clerk (JWT verified in FastAPI via JWKS endpoint)
Workers: Celery + Upstash Redis (broker)
Storage: Cloudflare R2 (S3-compatible)
Email: Resend
Payments: Stripe
## Core Profit Formula (NEVER deviate from this)
Net Profit = Attributed Revenue - Ad Spend - Attributed COGS - Estimated Returns - Platform Fees
All monetary values stored as INTEGER CENTS. Never floats for money.
Net Profit % = (Net Profit / Attributed Revenue) * 100
True ROAS = Attributed Revenue / Ad Spend
## 5-Tier Attribution Engine
Tier 1: Direct click ID match (fbclid/gclid in Shopify UTM params) — confidence 0.95
Tier 2: Conversion ID match (Meta Pixel / Google Tag event metadata) — confidence 0.85
Tier 3: SKU-weighted — distribute revenue proportional to campaign spend on matching SKUs — confidence 0.70
Tier 4: Blended — proportional across all active campaigns by spend volume — confidence 0.50
Tier 5: ML (XGBoost classifier trained on Tier1/2 ground truth) — confidence 0.60-0.85
## Multi-Tenancy Rules (CRITICAL — never break these)
Every DB table has org_id UUID column.
Every query MUST include WHERE org_id = :current_org_id.
Supabase RLS equivalent: SQLAlchemy always filters by org_id at service layer.
Never write a query that can return data from multiple organizations.
## Money Rules
Always store money as integer cents (e.g., $10.50 = 1050).
Always divide by 100 only at display layer.
Use Python Decimal for intermediate calculations, not float.
Never use float arithmetic on monetary values.
## Code Conventions
Python: snake_case, type hints on all functions, Pydantic v2 for request/response models.
TypeScript: camelCase, strict mode, no any types.
All API responses: { data: ..., error: null } or { data: null, error: { code, message } }
All timestamps: UTC ISO 8601 (e.g., 2026-02-13T10:30:00Z)
All IDs: UUID v4
## Security Rules
Never log OAuth tokens, API keys, or PII.
All platform tokens (Shopify, Meta, Google) stored AES-256 encrypted.
Idempotency: every sync job must be safe to run twice (upsert, not insert).
Audit log is append-only — never add UPDATE or DELETE to audit_log table.
## Error Handling
All external API calls (Shopify, Meta, Google) wrapped in try/except with specific error types.
Failed sync jobs: retry 3 times with exponential backoff (5min, 15min, 60min).
Platform API rate limits: raise specific RateLimitError, not generic Exception.
Never swallow exceptions silently — always log with context.
## Testing
After building each engine (attribution, profit, rules), write tests matching the SRS test scenarios.
Profit engine must pass: calculated value within ±1% of manually computed ground truth.
Attribution Tier 1+2: must correctly attribute ≥92% of orders with known click IDs.

Step 1 — Initiate OAuth:
  GET /api/connect/shopify?shop={shop_domain}
  Validate shop domain format (*.myshopify.com).
  Generate nonce, store in Redis with 10-min TTL.
  Redirect to: https://{shop}/admin/oauth/authorize
    ?client_id={SHOPIFY_API_KEY}

  GET /api/connect/shopify/callback?code=...&shop=...&state=...

💬 CURSOR PROMPT  —  Shopify order ingestion worker
Build app/workers/sync_shopify.py — Celery task for ingesting Shopify orders.
@celery_app.task(bind=True, max_retries=3)
def sync_shopify_orders(self, store_id: str, since_date: str = None):
  Load store from DB. Decrypt access token.
  If since_date is None, use 90 days ago.
  Call Shopify Orders API: GET /admin/api/2024-01/orders.json
    with params: status=any, created_at_min={since_date}, limit=250
  Handle pagination: loop while next page link exists in Link header.
  For each order:
    Upsert order record (UNIQUE on store_id + shopify_order_id).
    Upsert each line_item (quantity, unit_price_cents, sku, variant_id).
    Set unit_cogs_cents from line_item.cost_per_item if available, else NULL.
    Set unit_cogs_source = shopify if cost available, else estimated.
  Handle rate limits: if 429 received, wait rate_limit_delay from headers, then retry.
  Handle errors: on Shopify API 5xx, raise self.retry(countdown=300, exc=exc).
  Update stores.last_sync_at and stores.sync_status on completion.
  Log: orders synced count, errors, duration.
IMPORTANT: This job must be idempotent.
  Running it twice for the same date range must NOT create duplicate records.
  Use INSERT ... ON CONFLICT (store_id, shopify_order_id) DO UPDATE.
Also create sync_shopify_refunds(store_id, since_date) task:
  Fetch refunds from GET /admin/api/2024-01/orders.json?status=any (refunds are nested in orders)
  Upsert returns table for each refund line item.

@celery_app.task sync_meta_data(ad_account_id):

def tier3_attribute(order: Order, ad_insights: list, window_days: int) -> AttributionResult | None:
  Get all SKUs in this order from line_items.
  Get all active campaigns in the attribution window (last window_days days).
  For each campaign/ad_set:
    Calculate: sku_overlap_score = (sum of order line_item revenue for SKUs
      that this campaign was promoting) / total order revenue
    Note: We infer which SKUs a campaign promotes from historical order patterns.
      Use: for each ad_set, what SKUs appear most in attributed orders (Tier1/2 only)?
      Build a sku_to_campaign_affinity dict from existing Tier1/2 data.
  If any campaign has sku_overlap_score > 0:
    Distribute attribution proportionally to sku_overlap_score * ad_spend.
    winner = ad_set with highest (sku_overlap_score * spend).
    return AttributionResult(tier=3, confidence=0.70, ad_set_id=winner)
  If no SKU affinity data (insufficient Tier1/2 history): return None.
NOTE: Tier 3 requires at least 30 Tier1/2 attributed orders to build affinity data.
  If fewer than 30, skip to Tier 4.

def tier4_attribute(order: Order, ad_insights: list, window_days: int) -> AttributionResult:
  Get all active ad_sets in the attribution window with spend > 0.
  Calculate total_spend_window = sum of all ad spend across all platforms in window.
  For each ad_set:
    weight = ad_set_spend_in_window / total_spend_window

from decimal import Decimal, ROUND_HALF_UP
def calculate_profit_for_adset(
    org_id: str,
    ad_set_id: str,
    window_type: str,  # daily, 7d, 14d, 30d
    window_start: datetime,
    window_end: datetime,
) -> ProfitMetric:
  # 1. ATTRIBUTED REVENUE
  orders = load attributed_orders WHERE ad_set_id=X AND window within range
  attributed_revenue_cents = SUM(order.total_amount_cents) for these orders
  # 2. AD SPEND
  spend_cents = SUM(ad_insights.spend_cents) WHERE ad_set_id=X AND date in window
  # 3. ATTRIBUTED COGS
  attributed_cogs_cents = 0
  For each order in attributed orders:
    For each line_item in order:
      cogs = get_cogs_for_sku(org_id, line_item.sku, line_item.unit_price_cents)
      attributed_cogs_cents += cogs * line_item.quantity
  # 4. ESTIMATED RETURNS
  estimated_returns_cents = 0
  For each order in attributed orders:
    age_days = (now() - order.ordered_at).days
    if age_days >= 45:
      actual_returns = SUM(returns.refund_amount_cents WHERE order_id = order.id)
      estimated_returns_cents += actual_returns
    else:
      For each line_item:
        rate = get_return_rate_for_sku(org_id, line_item.sku)
        estimated_returns_cents += int(line_item.unit_price_cents * line_item.quantity * rate)
  # 5. PLATFORM FEES
  fee_rate = get_platform_fee_rate(org_id)  # default 0.029 (2.9%)
  platform_fees_cents = int(attributed_revenue_cents * Decimal(str(fee_rate)))
  # 6. NET PROFIT
  net_profit_cents = (attributed_revenue_cents - spend_cents
    - attributed_cogs_cents - estimated_returns_cents - platform_fees_cents)
  # 7. DERIVED METRICS
  net_profit_pct = (net_profit_cents / attributed_revenue_cents * 100) if attributed_revenue_cents > 0 else 0
  true_roas = (attributed_revenue_cents / spend_cents) if spend_cents > 0 else 0
  # 8. ATTRIBUTION COVERAGE
  total_orders_in_window = count orders placed in window
  attribution_coverage_pct = len(attributed_orders) / total_orders_in_window if total_orders_in_window > 0 else 0
  return ProfitMetric(all fields...)

--- FEATURE ENGINEERING ---
def build_features(order, ad_set, ad_insight) -> dict:
  return {
    "hour_of_day": order.ordered_at.hour,
    "day_of_week": order.ordered_at.weekday(),
    "days_since_campaign_start": (order.ordered_at - campaign.start_date).days,
    "order_value_cents": order.total_amount_cents,
    "order_value_vs_campaign_aov": order.total_amount_cents / campaign_avg_order_value,
    "campaign_spend_in_window_cents": ad_insight.spend_cents,
    "campaign_impressions_in_window": ad_insight.impressions,
    "customer_is_returning": 1 if customer_has_prior_orders else 0,
    "sku_campaign_affinity_score": sku_affinity_for_campaign(sku, campaign_id),
    "platform_meta": 1 if platform == "meta" else 0,
    "platform_google": 1 if platform == "google" else 0,
  }
--- TRAINING ---
def train_attribution_model(org_id: str):
  Load all Tier 1/2 attributed_orders as positive examples (label = correct ad_set_id).
  For each positive example, generate N negative examples
    (other ad sets active in same window = wrong answers).
  Build feature matrix X and binary label y (1=correct match, 0=wrong).
  Split: 80% train, 20% test.
  Train XGBoost classifier:
    model = xgb.XGBClassifier(n_estimators=200, max_depth=6, learning_rate=0.1,
      scale_pos_weight=neg_count/pos_count, eval_metric=auc)
    model.fit(X_train, y_train, eval_set=[(X_test, y_test)])
  Evaluate: AUC-ROC on test set. Must be > 0.75 before deploying.
  Log experiment with MLflow: mlflow.log_metric("auc", auc_score)
  Save model: mlflow.xgboost.log_model(model, "attribution_model")
  Save to Cloudflare R2: models/{org_id}/attribution_model_v{version}.pkl
--- PREDICTION ---
def tier5_attribute(order, ad_sets_active, model) -> AttributionResult | None:
  For each active ad_set in attribution window:
    features = build_features(order, ad_set, ...)
    score = model.predict_proba([features])[0][1]  # probability of correct match
  winner = ad_set with highest score
  confidence = winner_score (already 0–1)
  If winner_score < 0.55: return None (not confident enough, fall through to Tier 4)
  return AttributionResult(tier=5, confidence=confidence, ad_set_id=winner.id)
